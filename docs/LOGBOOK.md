## Архітектурні рішення (ADR у стислому вигляді)

* **SQLite замість серверної БД** — вузол автономний, без окремих сервісів, один файл, транзакції ACID.
* **Лише стандартна бібліотека у runtime** — запуск «з нуля» без `pip install` (простіше E3 та крос-ОС).
* **`Sensor` як інтерфейс** — муляж і реальний драйвер взаємозамінні; випадкові дані відтворюються через `seed`.
* **Outbox у тій самій БД** — атомарність «зберегти + поставити в чергу», переживає перезапуск.
* **Оброблення сміття на вході конвеєра** — одна точка довіри; муляж навмисно генерує сміття, щоб це перевіряти.
